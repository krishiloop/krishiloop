# Deviations from PROTOCOL_v1.md

Log every change to the pre-registered protocol here: the date, what changed, why, and whether any result had been seen.

| Date | Change | Reason | Results seen before the change? |
|---|---|---|---|
| 29 Oct 2026 | **Seeded per-class caps on large datasets** (subsamples, not full sets). Caps per class folder, seed 20261029: Dhan-Shomadhan 30 per folder (field and white-background folders separately), RiceyLeafDisease 60, RiceLeafDiseaseBD 150, Daffodil 100, RiceLeafBD camera-named 100, CCMT 150, tomato (jttrv2w27r) 150, potato West Bengal 400, potato Tanzania 2,500, SR University paddy 250, seasonal corn 250, eggplant (pwvpb658rm) 300, bean Rangpur 400. Exact lists of fetched members are in each dataset's `_fetch.json` on the 5090. | The lab link gives about 13 kB/s per connection to Mendeley (S3 eu-west-1) and Zenodo (measured 29 Oct, 14:53); full sets would take days. The protocol fixes no per-domain size; every capped domain still has more than the 100-image minimum. Full sets can be added later without changing any code. | No |
| 29 Oct 2026 | **RQ1 fold rule made explicit:** when a domain is held out, every domain of the same source dataset is excluded from training (not only the held-out domain), and classification is within the crop (the crop is known from the field record). Any training image whose near-copy cluster has a member in the held-out domain is removed. | The protocol defines a domain as dataset x capture x device, so one dataset can hold several domains (for example Dhan-Shomadhan field and white background). Training on a sibling domain of the same dataset would leak the dataset fingerprint that ml/vision showed dominates (99.6% dataset identification). This is the stricter reading of leave-one-domain-out. | No |
| 29 Oct 2026 | **De-duplication rule made explicit:** exact (SHA-256) and perceptual (pHash Hamming <= 6) matches are treated as copies: one copy is kept (from the dataset published first, then the larger image); if the copies carry different canonical labels, all are dropped. DINOv2-B near-copy clusters (cosine >= 0.95) are kept but grouped, so a cluster never spans a split. | The protocol lists the three tests but not what happens to each kind of match. | No |
| 29 Oct 2026 | **Device part of the domain id:** EXIF Make/Model when the device has >= 100 images in its dataset, else `other` (no EXIF: `unknown`). | The protocol says "device, where recorded"; tiny device groups would create domains below the 100-image minimum. | No |
| 29 Oct 2026 | **Backbone details fixed:** DINOv2 (B, L, G) at 224 px with the official DINOv2 linear-evaluation transform (resize 256, centre-crop 224), not the 518 px of the last training phase; "EVA-02 L" = EVA02-CLIP-L/14 (`open_clip` `EVA02-L-14`, `merged2b_s4b_b131k`, MIT), which also has a text tower; SigLIP 2 So400m = `ViT-SO400M-16-SigLIP2-384`. | The near-copy threshold (DINOv2-B cosine >= 0.95) was calibrated at 224 px in ml/vision; the protocol names "EVA-02 L" without a variant. | No |
| 29 Oct 2026 | **H3 details fixed:** standardised features, class-balanced logistic regression, weight decay picked on source validation from {1e-4, 1e-3, 1e-2} (the ml/vision probe grid); for H1 and H3 the temperature is fitted on source validation (20% of source clusters). | The protocol names H3 without hyperparameters. Nothing is tuned on a target domain. | No |
| 29 Oct 2026 | **RQ1 scoring minimum:** a held-out domain is scored only if it has >= 100 kept images and >= 2 labels shared with training (the protocol's 100-image minimum applied per domain); smaller device sub-domains (for example RiceyLeafDisease `other`, 56 images) stay in the manifest and in training but are not scored on their own. | The protocol states the minimum per dataset, not per domain. | No (fixed in code before the first RQ1 run) |
| 29 Oct 2026 | **White-background sets kept as labelled `lab` domains:** Dhan-Shomadhan white-background folder, PaddyPulse-SLNR (Sri Lanka), BRACOL. CCMT is labelled `mixed` (its method lists white, dark, illuminated and real backgrounds without per-image tags). | Allowed by section D ("a white-background set may enter only as an explicitly labelled lab domain"); recorded here so readers can drop them. | No |
| 29 Oct 2026, 15:50 | **pHash matches must be confirmed before a copy is dropped.** New rule: a perceptual match (pHash Hamming <= 6) is treated as a copy and dropped only if DINOv2-B also gives cosine >= 0.95 (exact SHA-256 copies are still always dropped). Unconfirmed pHash matches are kept but placed in the same cluster, so they still never span a split. This replaces the 15:2x rule in the row above. | A check with the protocol's own DINOv2-B instrument (`kl_research/overlap.py`, `overlap_report.json`) showed that pHash <= 6 flags different photos on low-resolution or uniform sets: 0 of 299 cross-dataset pHash pairs were near-copies (median cosine 0.50; 13 pairs even crossed crops, maize vs rice); within datasets, only 1.5% (Daffodil) and 13% (Netrokona, 224 px PNGs) of pHash pairs were near-copies, against 86 to 97% for BD5, RiceLeafDiseaseBD, RiceyLeafDisease and Sethy. Under the old rule, distinct photos were dropped as "duplicates" and 115 images as false cross-dataset "label conflicts". | **Yes:** an interim RQ1 run under the old rule (8 held-out domains, 4 backbones) had been seen. It is kept, unchanged, as `results/rq1_interim_strict_phash.{json,md}` and is reported next to the final numbers. The new rule changes which images are dropped, not any evaluation setting. |
| 29 Oct 2026 | **Transport through verified mirrors:** iBean comes from the creators' own Hugging Face repository `AI-Lab-Makerere/beans` (the original Google Cloud Storage zips answer 403); Tanzania potato images come from the AgML Hugging Face re-zip, and only members whose file name, size and CRC32 equal the Zenodo deposit are used. Licence, citation and provenance stay those of the original deposit. Approved by the lead, 29 Oct. | The Zenodo route runs at about 13 kB/s per connection; the Hugging Face CDN at about 1.1 MB/s. | No |
